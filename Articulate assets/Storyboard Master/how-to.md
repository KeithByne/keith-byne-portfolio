# Storyboard Master

Use this for every client and every portfolio module. Copy the blank Word file. Do not invent a company or a logo. The client supplies artwork.

**Formatting is locked. Content is not.** Change the words in the cells whenever the job needs it: company, project, aspect ratio, aim, notes, assets, format, screen copy, and interactions. Do not rename labels, move rows, change type sizes, fills, page size, or page breaks.

## Always produce two files

1. **Storyboard** — the full Word document.
2. **Brand Guideline ROM** — pages 1–2 only, PDF named `Company Name_Project Name.pdf`. Open it in a browser to pick colours into Rise 360 or Storyline 360.

## Before any Rise 360 or Storyline 360 work

Do these four things on every job, including a portfolio module. Then open the authoring tool.

1. **Production asset list.** One landscape page, after the brand pages and before the block and slide tables. It names every asset that production will use: backgrounds, a company logo, icons, characters, audio, a downloadable job aid, and any other file or treatment. Each line has a name, what it is, where it is used, and a status: **In hand**, **Client supplies**, or **Still to make**. Leave out anything that production will not use.
2. **Build gate.** Do not open Rise 360 or Storyline 360 for that job until the list exists and every line is **In hand** or **Client supplies**. Anything still unknown goes in `open-questions.md` as `[TO CONFIRM]`. Do not invent a logo, a photo, or a stand-in file.
3. **The storyboard is the source of truth.** Learner-facing words are written in Screen Copy first. If a word changes inside Rise 360 or Storyline 360, write it back into the storyboard before the next session. The published module matches the storyboard.
4. **One name for one thing.** The name on the production asset list is the name in that slide’s Assets cell and the name of the file. Do not give the same file a second name. Do not write “same as another slide.”

## Page order

| Page | Layout | Content |
|------|--------|---------|
| 1 | A4 **portrait** | Block 01 written brand (no outer frame) |
| 2 | A4 **landscape** | Block 02 fonts and Block 03 colour scale (no outer frames) |
| 3 | A4 **landscape** | Production asset list |
| 4 onwards | A4 **landscape** | Storyboard list: Rise **blocks**, then Storyline **scenes / slides / layers** |

The PDF is always A4, with a page break after every page. It is never one continuous sheet.

No block crosses a page break. A block is Block 01, Block 02, Block 03, one page of the production asset list, or one storyboard table. If the block does not fit, the whole block moves to the next page.

Do not repeat Block 01 on the storyboard pages. Storyboard tables keep cell frames. Information text is 14pt. Label text is 16pt bold, on the step fill `#E6E6E6`.

## Block 01 labels

The title bar is the title of that page. It is not a content row.

1. Title bar: Block 01 · Brand guideline (written)
2. One small row with no fill
3. Company
4. Project
5. Aspect Ratio
6. Project Aim
7. Alignment
8. Logo / artwork
9. Notes

## Storyline background images

When a Storyline 360 module uses an image background, make 16:9 files at 1920 × 1080. The normal set is five. One name each, on the production asset list and on the slides that use it.

| Name | Use it on |
|------|-----------|
| Background title | The welcome slide only |
| Background base | Working slides: conversation, choices, steps, close |
| Background do | Full slides on the allowed path |
| Background don't | Full slides on the stop path |
| Background results | The completion slide |

A feedback layer dims the base slide. It does not get its own background image. Rise 360 blocks keep a solid paper fill unless that job’s list says otherwise.

## Production asset list labels

One table on each A4 landscape page. That page is one block, so the table stays on that sheet.

1. Name
2. What it is
3. Where it is used
4. Status

## Storyboard table labels

Each block, scene, slide, or layer is one table, with a blank line between tables.

1. Assets
2. Format
3. Screen Copy
4. Interactions
